# agrodss 마일스톤 — 시계열 정리

작성 2026-09-18. 재료는 `design_tree_review_20260918.md`(트리 평가 §1~§6)와 발행자 결정
넷(별도 신축 · 이식 없음 · 몰 중심 수익 · 영상이 상세페이지). 저장소 VELA 는 **경험**으로만
쓴다.

## 0. 시간축을 무엇으로 잡는가

달력 날짜는 아직 못 박는다 — 첫 농가·첫 작목이 미정이고 그것이 유일한 임계(M1)다.
대신 **T = 첫 작목의 기준일(정식일 또는 파종일)** 을 원점으로 둔다. 이유는 트리에 있다.

```
DSS 첫해 값 넷(L)     정식일·품종만으로 성립 → T 이전에 서 있어야 값이 있다
몰 수익               첫 수확이 있어야 납품 → T + 생육기간 이전에 열려 있어야 한다
경계(G1 방화벽)        두 시스템이 한 DB 를 쓰기 전 → 코드 첫 줄 이전
```

그래서 순서는 **결정 → 경계·스키마 → (몰 MVP ∥ DSS 첫해 넷) → 첫 시즌 → 2년차 → 3년차**다.
몰과 DSS 는 병렬이지만 **공유 스키마가 둘보다 먼저**다.

기호: ◇ 시스템 밖(발행자·농가의 일) · ■ 코드 · □ 종이(문서·스키마) · ⏱ 계절에 묶임

## 7b. 내부 화면 원칙 (발행자 제정 2026-09-18 — 대장 D-6 · M-13)

**외부 배포는 하지 않고, 내부적으로는 진행하는 대로 화면이 보여야 한다.** 화면은 단계
끝의 산출이 아니라 **매 단계의 관문**이다 — 화면에 없으면 완료가 아니다.

**화면의 정의 (발행자 확인 2026-09-18)**: Claude Code 세션 패널에 띄우는 렌더가 아니다.
**별도 프론트엔드 앱**이 localhost 서버로 떠 있고 **브라우저 새 창**에서 보여 주는 화면이다.
세션 패널 렌더(`render_backlog.py`)는 그 앱이 서기 전의 임시 수단이며 M-13 관문을 채우지
않는다. M-13 의 첫 산출은 이 앱의 골격 — 첫 페이지가 대장·트리를 보여 준다.

| 단계 | 그 단계의 화면 | 성격 |
|---|---|---|
| 0 결정 | 대장 · DSS 트리 · 몰 트리 (정적 렌더, `docs/render_backlog.py` 가 시작점) | 종이의 화면 |
| 1 경계·스키마 | 스키마 뷰어 — 격자 칸 · 층 · 경계 필드(허용/금지)를 표로 | 종이의 화면 |
| 2A 몰 MVP | 상세페이지 목업 — 영상 자리 + 촬영 시각·필지 메타. 주문·정산은 화면 흐름만 | 몰 |
| 2B DSS 첫해 넷 | 산출 화면 — 수확기 예측 · 달력 경보 · 방제력 대조 · 예찰. 산출 7종의 종류가 화면에 구분돼 보인다 | DSS |
| 3 첫 시즌 | 필지 타임라인 — 사건·영상·판정이 한 축에 | 운영 |

- **localhost 뿐이다.** 공개 URL · 도메인 · 클라우드 · 외부 포트 없음. 해제 시점은 발행자 결정(D-6).
- 화면은 4층(전달)이다 — 1·2층에 직접 닿지 않는다. 화면이 3층 산출만 받는다는 것을 단계 1 에서 검사로 고정.
- 몰 화면과 DSS 화면은 **같은 로컬 호스트의 다른 경로**로 시작해도 되지만 경계(M-3)는 화면 이전에 서 있어야 한다.

## 8. 마일스톤이 아닌 것 (명시)

- **180종 전체 격자** — 어느 단계에도 없다. 기준만 정하고 배정은 필요할 때(C).
- **토양 수분 관측 · 전염원 근접성 · 야간 조명 API** — 존재하지 않는다. 추정·입력·다농가로
  대신하며, 축은 등록해 두고 "없어서 못 한다"를 말한다(E).
- **VELA 코드 이식** — 폐기. 외부 원천 목록과 "가져가지 말아야 할 것"만 경험으로.
