# I-3 — 입력 5종

**무엇을 지키려는가**: 시스템이 물어야 하는 것의 **형태**를 닫는다. 트리 G 의 3종(필지 ·
사건 · 관찰)으로는 역산의 목표일 · 되먹임의 불이행 사유 · 마을 단위의 공유 동의가 들어올
자리가 없었다. 자리가 없으면 그 데이터는 영원히 안 모인다.

작성 2026-09-18. 대장 I-3. 근거: 평가서 §4 #3 · §3-2 입력 고아 8건.

## 0. 공통 필드 (모든 레코드)

| 필드 | 뜻 | 왜 |
|---|---|---|
| `source` | 누가/무엇이 썼나 — `farmer` · `external:<원천>` · `computed` · `mall:settlement` · `video:reading` | 원장 출처 3칙. 읽기 전 "누가 쓰는지"를 안다 |
| `recorded_at` | 입력 시각 | |
| `observed_at` | 대상 시각(관찰·사건이 실제 일어난 때) | 입력 시각과 다르다 — 1층 "관측 시각"은 이것 |
| `resolution` | 해상도(필지/재배 단위/읍면동/관측소…) | 1층 3요건 |
| `subject` | 필지 × 재배 단위 | 몰 상품 키와 같다 |

`source` 가 없는 레코드는 1층에 진입하지 못한다. 테스트는 운영 원장에 쓰지 않는다 —
첫 코드부터 격리 픽스처를 짝으로 둔다(VELA: 도입 당일 오염 2건).

## 1. 필지 고정 정보 `parcel`

위치 · 면적 · 작목 · 식재년도 · **용도**(자가/판매/몰 납품) · 토성 · 경사 · 배수 · 미기상
3문항 · 야간 조명 · **재배 환경**(노지/시설 — C 에서 G 로 누락됐던 것) · **관수**(유무·방식 —
B0 에서 옮겨 옴, 필지마다 다르다) · **인증 유형**(법정 + 몰 기준 — 2단계 시점 결정, 전환
개시일 포함).

원천: 위치는 지적 원천(◐), 토성·배수는 공공 토양도 초기값 후 농가 확인(◐), 나머지 ▲.
**계산 가능한 것은 묻지 않는다** — 고도·일장은 위치에서 계산.

예비농(후보 필지)은 지금 열지 않는다(U-12).

## 2. 사건 `event`

파종 · 정식 · 방제 · 시비 · 관수 · 수확 · **촬영** · **납품**. 각각 시각 · 자재/도구 · 수량.

| 부속 필드 | 뜻 |
|---|---|
| `advice_ref` | 어떤 조언에 따른 사건인가(없으면 자발) |
| `quantity` · `quality_grade` · `return_reason` | 수확·납품에서 — **결과 기록**. 몰 정산이 채운다(`source=mall:settlement`) |

`return_reason` 은 갈래를 나눈다 — 품질 결함(→ 결과 기록) / 배송·변심(→ 몰 내부, DSS 에
오지 않음). 안 나누면 변심이 "품질 실패"로 남는다.

## 3. 관찰 `observation`

가장 값지고 가장 받기 어렵다. 세 통로:

| 통로 | 형태 | 등급 |
|---|---|---|
| 농가 발화 | 질의 자체("꽃이 안 핀다") — **이중 사용** | 최종 심급 |
| 직접 관찰값 | 결구 충실도 · 흙 쥐어보기 결과 | 최종 심급 |
| 영상 | 파일 + 촬영 시각 + 필지 + 해상도 — **1층 사실** | 사실 |
| 영상 판독 | 영상에서 읽은 생육 상태·병징 | **2층 파생 · 추정 등급** — 판단 축이 아니라 확인 요청 트리거 |

`observed_at` 이 필수인 유일한 이유가 여기 있다 — "지난주에 봤는데 오늘 적는다".

## 4. 계획 `plan` (신설)

| 항목 | 원천 | 비고 |
|---|---|---|
| 목표일(납품 계획일 · 출하 목표일) | `farmer` | **F 역산의 입력.** 몰 수요가 정한 것이면 조언 입력이 되므로 `source=farmer` 만 허용 |
| 방제력 채택 | 표준 방제력 → 농가 채택 | 1층 계획 데이터 — 계획 대 실제 대조의 기준 |
| 작기 계획 | 다작기 작목의 작기 선택 | 격자 단위를 정한다 |

## 5. 결정 `decision` (신설)

| 항목 | 뜻 |
|---|---|
| 조언 채택 / 불이행 + **사유** | 되먹임 두 번째 칸. *"안 따른 이유가 조언보다 값지다"* |
| 선택지 산출에 대한 선택 | I-1 §2-2 의 짝 — 선택지+대가는 결정으로 닫힌다 |
| 공유 동의 · 범위 | 마을 단위(K)의 입력 고아 해소 |
| 인증 전환 개시 | 소급 불가 결정의 기록 |

불이행 사유는 **묻는 시점**이 관건이다 — 조언 시점이 아니라 그 사건이 기록되지 않은 채
창이 지났을 때(계획 대 실제 대조가 트리거). 조언 직후에 물으면 아무도 안 적는다.

## 6. 몰 → DSS 경계와의 대응 (I-5)

| 몰이 주는 것 | 들어가는 입력형 | 허용 |
|---|---|---|
| 영상 | 관찰(영상) | 허용 |
| 수확량 · 품질 등급 · 반품 사유(품질) | 사건(수확·납품) 결과 기록 | 허용 |
| 납품 계획일 | 계획 — `source=farmer` 일 때만 | 조건부 |
| 재고 · 주문 잔량 · 판매 속도 · 정산액 · 리뷰 | (없음) | **금지** — 들어갈 입력형이 없다 |

금지 항목에 **입력형이 없다**는 것이 경계의 첫 번째 방어다. 스키마에 자리가 없으면 들어올
수 없다. 두 번째 방어(검사)는 I-5.

## 7. 검사 (M-6 마이그레이션에서)

- 5종 전부 `source` NOT NULL(거부 — 없는 레코드는 실패).
- 계획의 목표일에 `source != farmer` 를 넣으면 실패(거부) / `farmer` 는 통과.
- 테스트가 운영 원장 경로에 쓰지 못한다(격리 픽스처 주입 검사).
