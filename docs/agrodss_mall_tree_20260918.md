# agrodss 몰 트리 초안 — DSS 트리와 같은 형식

작성 2026-09-18. 마일스톤 0-2 의 산출물. 형식은 발행자의 DSS 트리(A~N)와 같다 —
항목 · 외부 API 표기 · 연결(→ 소비자 / ← 입력원) · 고아. 기호는 평가서 §0 과 같다
(● 필수 API · ◐ 보조 · ○ 계산 · ▲ 입력 · — 무관).

**이 트리는 전부 추론이다.** DSS 트리에 실질의가 들깨 하나였듯, 몰 트리에는 실주문이
0건이다. 첫 납품 농가와 첫 주문이 생기면 B~E 가 바뀐다.

DSS 트리 항목은 `DSS:` 접두로 가리킨다(예 `DSS:D 격자 단위`).

---

## 몰-A. 전제

- 수익원은 몰이다. DSS 는 이 몰에 납품하는 농가를 위한 것이고, 몰 수익이 DSS 를 먹인다
  → 농가에게 DSS 는 **납품 조건이지 구독 상품이 아니다** (`DSS:L` 첫해 이탈의 해법)
- 대원칙: **현장 영상이 상세페이지를 대체한다** — 텍스트·연출 사진이 아니라 시계열 영상
- 파는 것은 품질이 아니라 **연속성**이다 (`DSS:H G3` 를 몰이 그대로 물려받는다)
- 소비자 도달 3조건(`DSS:H G1·G2·G3`)은 몰에서 첫날부터 참이다 — DSS 안에서는 규칙,
  몰에서는 **제품 정의**
- 답하지 않는 것: 가격 예측. 몰 가격은 계약이다 (`DSS:F 답하지 않음` → *대상 아님*)

## 몰-B. 상품 단위

- **상품 = 필지 × 재배 단위** — `DSS:D 격자 단위`(연속된 재배 일정)와 **같은 키**
  - 이유: 영상(촬영 시점 칸) · 판정(3층) · 정산(결과 기록)이 한 키로 이어진다
  - 키가 다르면 세 곳에 매핑 표가 생기고, 매핑 표는 `DSS:G1 고아` 계열의 온상
- 상태: 생육 중(예약) / 수확 / 판매 중 / 품절 / 취소
- **예약 판매**가 자연스럽다 — 생육 중 영상이 곧 상품 소개이므로 수확 전에 팔린다
  - 대가: 수확 실패(`DSS:F 상한 제약` — 한파·강우) 시 환불 규칙이 필요 → 몰-I
- 단위 수량: 필지 예상 수량(`DSS:L 수확기 예측`의 짝 — 수량 예측은 트리에 없음, 몰-N)

## 몰-C. 영상

- 촬영 시점은 `DSS:D 격자 칸`("이 단계에서 이 장면") — 상세페이지 재료이자 관찰 기록
- 메타 필수: 촬영 시각 · 위치(필지) · 해상도 — **없으면 게시 불가** (`DSS:F 1층 진입 3요건`과
  같은 규칙, 몰 쪽 사본)
- 편집 원칙: 무편집 또는 자르기만. 연출·보정은 "현장 영상" 정의를 깨뜨린다
- 소비자가 보는 것: **시계열 목록**(파종→정식→생육→수확). 최신 1개가 아니다 — 연속성이 상품
- 영상 → 판독(생육 상태·병징)은 `DSS:2층 파생`, 신뢰 등급 추정. 상세페이지에 판독을
  싣지 않는다(싣는 순간 몰-G 노출 판정 문제)
- ● 외부: 영상 저장·트랜스코딩·스트리밍(CDN) — 자체 구축 금지 영역
- 개인정보: 영상에 사람 얼굴·차량 번호·주소 표지가 들어간다 → 몰-I

## 몰-D. 주문 · 결제 · 배송

- ● 결제 대행(PG) · ● 본인확인/간편로그인 · ● 택배 예약·추적 · ● 도로명 주소 검색
- 전부 외부다. **자체 구축하지 않는다** — 몰의 값은 영상과 연속성이지 결제가 아니다
- 배송 단위와 상품 단위(몰-B)가 다르다 — 한 필지 수확이 여러 주문으로, 여러 필지가
  한 주문으로. 매핑은 몰 안에서 닫힌다(DSS 로 가지 않음)

## 몰-E. 정산 · 결과 기록

- 농가 정산: 수량 · 품질 등급 · 반품 사유 · 정산액
- 이 중 **DSS 로 흐르는 것**(`DSS:J 결과 기록`, 허용 쪽): 수확량 · 품질 등급 · 반품 사유
- **흐르지 않는 것**(금지 쪽): 정산액 · 재고 · 주문 잔량 · 판매 속도 → 몰-H
- 반품 사유는 두 갈래다 — 품질 결함(→ DSS 결과 기록) / 배송·변심(→ 몰 내부). 갈래를
  안 나누면 변심이 DSS 에 "품질 실패"로 기록된다

## 몰-F. 입점 · 기준

- 몰 자체 기준(인증 · 품질 · 영상 의무)이 `DSS:관통 축 인증`에 **또 하나의 인증 유형**으로
  등록된다 — 2단계 시점에 결정, 소급 불가
- 납품 적합 필지 판정: `DSS:B0 용도(판매)` 의 몰 판. 부적합 필지를 상품 사슬에 태우지 않음
- 인증 표기: 법정 인증(유기·무농약)은 **인증서 없이 표기 금지** — 안전·법규 판단이라
  확인 요청 범위 1 (`DSS:자율 운영 규율`). 인증 여부 조회 API 는 없다(▲ 인증서 사진 + 입력)
- 첫 납품 농가 입점 = `DSS:M1` 의 몰 조건

## 몰-G. 소비자 노출 판정 (결정 0-3 대기)

- 노출한다면: 판정 + 관측일 + 판정 기준이 반드시 붙는다(`DSS:H G2`). 산출 7종 중
  "판단함"만 노출, "판단 불가·해당 없음"은 노출하지 않음
- 노출하지 않는다면: G2 는 DSS 내부 규칙으로 남고 몰-C 영상만 소비자에게 간다
- 노출의 대가: DSS 판정이 **판매 문구**가 된다 → `DSS:K 시장 신호`가 판정 단위로
  즉시 발생. 이 트리의 권고는 **첫 시즌은 비노출** — 판정의 3/3 재현이 확인된 뒤 결정

## 몰-H. 경계 (G1 방화벽 — `DSS:§6-3`)

```
몰 → DSS  허용   영상(1층) · 수확량 · 품질 등급 · 반품 사유(품질 갈래) · 납품 계획일(농가가 정한 것)
몰 → DSS  금지   재고 · 주문 잔량 · 판매 속도 · 정산액 · 리뷰 평점 · 몰 수요 예측
DSS → 몰  허용   판정 + 관측일 + 기준(노출 결정 시) · 촬영 시점 알림
DSS → 몰  금지   농가 필지 상세(주소·검정값) — PII
```

- 래칫: 3층 판단 입력 스키마에 금지 필드가 없다 / 허용 필드는 흐른다 (양방향)
- 납품 계획일은 **농가가 정한 것**이면 허용(`DSS:F 역산` 목표일), 몰 수요가 정한 것이면
  금지. 같은 필드가 출처에 따라 갈린다 → 필드에 `source` 필수(`DSS:원장 출처 3칙`)

## 몰-I. 법규 · 개인정보

- 통신판매업 신고 · 전자상거래법 청약철회 규정 — 예약 판매·수확 실패 환불 규칙이 여기 걸림
- 농산물 표시: 원산지 · 인증 표시 · 등급. 인증 표기는 몰-F
- 영상 PII: 얼굴·번호판·주소 표지 → 게시 전 처리 또는 촬영 지침. 덤프 저장 금지 규율과
  같은 축(`DSS:프롬프트 후킹 PII`)
- 세금계산서·현금영수증 — 정산(몰-E)의 외부 의무. ● 국세청 API 또는 PG 부가 서비스

## 몰-J. 되먹임 (몰 쪽)

- 소비자 반응 → 농가: 반품 사유(품질)만 DSS 를 거쳐 간다. 리뷰·평점은 **가지 않는다**
  (수요 신호 = 금지 쪽)
- 몰 → 촬영 지침 개선: 어떤 시점 영상이 구매로 이어지는가는 **몰 내부 분석**이지
  DSS 축이 아니다. 섞이면 촬영 시점 칸이 판매 최적화로 휜다(`DSS:A1` 훼손의 몰 판)

## 몰-K. 다농가

- 같은 작목 여러 농가 → 소비자 비교 → 시장 신호(`DSS:K`). 첫 농가 한 집일 때는 없다
- 병해충 공유(`DSS:K`)는 몰 데이터가 아니다 — 몰은 발생 정보를 갖지 않는다
- 농가 간 노출 형평: 영상 연속성이 긴 농가가 유리 → 이것이 "연속성을 판다"의 의도된 결과

## 몰-L. 첫 시즌

- 첫 시즌 몰이 주는 값: 판로(농가) · 현장 영상(소비자). DSS 가 없어도 성립 — 그래서 몰이 먼저
- 첫 시즌에 없는 것: 비교(농가 1) · 리뷰 누적 · 예약 판매 실적
- 첫 주문 1건이 몰 트리의 실증점(DSS 의 들깨에 해당)

## 몰-M. 순서 (마일스톤 2A 와 대응)

1. 상품 키 = 격자 단위 확정 (몰-B) — 단계 1 스키마와 함께
2. 영상 메타 규칙 · 촬영 시점 칸 (몰-C) — 격자 스키마에 칸 추가
3. 경계 스키마 (몰-H) — 마일스톤 1-1 과 동일 항목
4. 외부 계약: PG · 택배 · CDN · 본인확인 (몰-D) — 시스템 밖
5. 입점 기준 · 인증 표기 규칙 (몰-F · 몰-I)
6. 첫 농가 입점 → 첫 영상 게시 → 첫 주문

## 몰-N. 미해결

- **수량 예측** — 예약 판매 단위 수량의 원천이 DSS 트리에 없다(수확기 예측은 시기만)
- 수확 실패 환불 규칙 — 상한 제약 사건(한파) 시 예약 주문 처리
- 노출 여부(결정 0-3)
- 영상 판독 자동화를 할지, 한다면 확인 요청 트리거로만 쓸지
- 유입 경로(마케팅) — 수익원인데 트리에 항목이 없다. **누락**이지 고아가 아니다

|---|---|---|---|

| 몰-D 결제 | PG | ● | |
| 몰-D 본인확인·로그인 | 간편인증/소셜 로그인 | ● | |
| 몰-D 배송 | 택배 예약·추적 | ● | |
| 몰-D 주소 | 도로명 주소 검색 | ● | |
| 몰-E 세금 | 국세청 또는 PG 부가 | ● | |
| 몰-F 인증 확인 | 없음 | ▲ | 인증서 사진 + 입력. VELA 경험: 인증 조회 API 부재 |

## 연결 요약 (몰 ↔ DSS)

```
몰-B 상품 키        = DSS:D 격자 단위                 (같은 키)
몰-C 촬영 시점      = DSS:D 격자 칸(신설)              (같은 칸)
몰-C 영상 메타      = DSS:F 1층 진입 3요건             (같은 규칙)
몰-E 결과 기록      → DSS:J 되먹임                     (허용 필드만)
몰-F 입점 기준      → DSS:관통 축 인증 유형             (추가 유형)
몰-G 노출 판정      ← DSS:3층 판단함 + H G2            (결정 0-3)
몰-H 경계           = DSS:H G1 · §6-3                  (같은 스키마)
몰-B 예약 판매      ← DSS:F 상한 제약                  (환불 트리거)
몰-N 수량 예측      ← DSS (없음)                        입력 고아
```

## 고아

| 항목 | 판정 |
|---|---|
| 몰-N 수량 예측 | **입력 고아** — 예약 판매가 요구하는데 DSS 에 원천이 없다. DSS 트리 E 에 "수량" 축을 넣을지, 몰이 농가 입력(▲)으로 받을지 결정 필요. 권고: 첫 시즌은 ▲ |
| 몰-J 리뷰·평점 | **의도된 고아** — 소비자가 없는 것이 아니라 DSS 로 가지 않기로 한 것. 검사로 고정 |
| 몰-D 배송 매핑 | 몰 내부에서 닫힘 — 고아 아님 |
| 유입 경로 | **누락** — 트리에 항목 자체가 없다 |
