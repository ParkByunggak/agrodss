## 3. 되먹임 레코드 네 종

| 종류 | 누가 쓰나 | 무엇 |
|---|---|---|
| `feedback.request` | 농가 · 발행자 | **사용자 개선 요구** — 직접 말한 것이라 오탐일 수 없다(다리 B). 상태 접수→검토→채택→반영/거부/보류 |
| `feedback.prediction` | `computed:judge` | **예측 원장** — 판단함의 대조 가능한 주장만(수확 창 · 경보 목록 · 놓침 목록). 바뀔 때만 한 줄 |
| `feedback.outcome` | `computed:evolve` | **대조 결과** — 예측 ↔ 사건 원장. 적중 / 빗나감 / 대조 불가(사건이 없으면 값을 안 메운다) |
| `improvement.item` | 셋 다 | **개선 항목** — 자기개선 업무의 단위. 출처(origin)가 없으면 스키마가 거부한다 |

## 4. 자율진화 루프 (judge/evolve.py)

```
측정  measure    예측 ↔ 사건        수확 사건이 창 ±오차 안이면 적중, 밖이면 빗나감
                                    창이 지났는데 수확 사건이 없으면 '대조 불가' + 입력 제안
제안  propose    빗나감            → 보수(등급 상한, 자동) + 확장(격자 창 재검토, 제안)
                 불이행 사유       → 확장(작업 칸 lead_days·retry 재검토, 제안)
                 개선 요구(접수)   → 개선 항목 + 요구는 '검토'로
채택  사람       확장 방향은 farmer · publisher 만 채택·반영할 수 있다(computed 가 하면 거부)
적용  apply_caps 봉투가 나온 뒤 · 돌려주기 전 · 한 번 — 등급만 낮춘다, 규칙은 안 바꾼다
검증  record_verification   라이브 독립 3회 3/3 — 같은 세션 재판정은 1회로 센다
```

### D-14 자율 적용의 범위 — 보수만

```
보수   등급 하향 · 판단 불가 전환 · 범위 축소      자동 적용 가능 — 되돌릴 수 있고 범위가 좁다
확장   임계 · 규칙 · 격자 칸 · 사전 변경           제안까지 — 사람이 채택한다
```

왜: 자율진화가 확장을 스스로 하면 *"시스템 발언 = 시장 신호"*(K)와 A1(일차 기능이 최적화로
휘는 것)을 시스템이 자기 손으로 어긴다. 보수는 어겨도 손해가 "덜 말한 것"뿐이다(P-3 아무것도
안 하는 쪽). 스키마도 같은 것을 본다 — `auto_applied=True` 이면서 `direction=확장` 인 레코드는
스키마에서 죽는다.

### 두 번 적지 않는다

같은 (재배 단위 · 결정) 의 같은 payload 예측 · 같은 예측의 같은 판정 · 같은 출처의 개선 항목은
두 번 안 만든다. 그래서 `evolve.cycle()` 은 몇 번 돌려도 같다(검사 있음).
