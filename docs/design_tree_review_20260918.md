## 3. 고아 항목

정의를 셋으로 가른다. 참조 0 만 보면 "안 하기로 한 것"과 "빠뜨린 것"이 구분되지
않는다(CLAUDE.md 규율).

### 3-1. 출력 고아 — 있는데 소비자가 없다 (저장소 G1 형태)

| 항목 | 상태 | 판정 |
|---|---|---|
| **B11 경영** | 입력(소득 목표·지출)은 받는데 산출이 없다 | 빠뜨린 것 — 상시 군이라면 산출 정의 필요. 아니면 "B10 판매의 부속"으로 격하 |
| **B9 수확 후 관리** | 저장성만 들어오고 나가는 선이 없다 | 얇음 — 저장 후 출하 시점 판단(B10 입력)으로 이어야 함 |
| **E 적산온도** | 계산 축으로 등록만 되고 트리에 소비자 없음(B6·L 이 암묵 소비) | 명시 누락 — 저장소에는 `gdd_engine.py` 가 있어 실제로는 소비됨. 트리만 고친다 |
| **D 준비 착수일 → 다른 단계로 넘어감** | F 선제 발화가 이 갈래를 안 받는다 | 명시 누락 |

| **C 필지 속성(노지/시설)** | G 가 안 받는다 | 빠뜨린 것 |

### 3-2. 입력 고아 — 요구하는데 원천이 없다 (G1 반대 형태)

| 항목 | 요구하는 입력 | 트리 내 원천 |
|---|---|---|
| **F 역산 구조** | 목표일 | 없음 — G 3종에 "계획"형이 없다 |

G "물어야 하는 3종"이 좁다 — 계획(목표일) · 결정(불이행 사유·동의) 두 형이 더 있다.

## 5. 합리성 총평

- **자기 한정이 일관되다.** 차이 탐지 · 답하지 않을 자리 · 통제 불가는 판단 않음 ·
  농가 관찰 최종 심급 · 대리값 금지 — 다섯 항목이 한 원칙("시스템이 가진 것만 더한다")
  의 다른 표현이고 서로 모순이 없다. 저장소의 헌법·CLAUDE.md 규율과도 같은 결이다.
- **비용 판단이 옳은 곳**: 품종 보정 2종(대부분 칸 보정 없음) · 버섯 경계만 긋기 ·
  180종 배정 유보 · M4 종이 위 한 바퀴 · 병해충 ① 뒤로 · 일장 계산(오차 0).
- **비용 판단이 약한 곳**: H 임계를 비용 비로 정한다는 원칙은 옳으나 비용 데이터의
  원천이 없어 첫해에는 정성 임계로 갈 수밖에 없다 — 그것을 명시해야 "임계는 비용
  비"가 첫해에 거짓이 되지 않는다.
- **외부 API 관점**: 트리가 첫해 값이라고 꼽은 넷(표준 방제력·달력 경보·수확기
  예측·광역 예찰)은 **전부 이미 연동된 원천**(농사로·KMA·GDD·NCPMS)으로 성립한다.
  반대로 트리가 "뒤로" 미룬 것(전염원·토양 수분·야간 조명·미기상)은 **API 가 존재하지
  않는 것들**이다 — 미룬 이유와 API 부재가 일치한다. H 자재 분리·유기 임계가 요구하는
  공시자재도 **이미 연동돼 있다**(정정 참조 — 초판의 "하나 남았다"는 도구 오류였다).
  **첫 농가 전에 새로 붙여야 하는 외부 API 는 없다.** 남는 것은 두 가지 확인이다 —
  ①농자재 3종 키(PIS·비료공정규격·종자)의 2026-06-08 이후 승인 여부 ②공시자재
  정본의 라이브 신선도 — 저장소 사본은 fetched_at 2026-09-07(09-13 커밋 095479f)이고
  주 1회(월요일) 스케줄이면 라이브에는 09-14 수집분이 있어야 한다. 저장소로는 알 수 없다.
  라이브 파일의 fetched_at 을 보고, 없으면 스케줄러 미가동 또는 급감 보류를 의심한다.
- **트리의 자기 고백**("전부 추론, 실질의는 들깨 하나")이 정직하고, M1 을 유일한
  임계로 둔 것과 일치한다. 위 정합성 위반 14건 중 즉시 4건은 첫 농가와 무관하게
  구조에서 나온 것이라 M1 전에 고쳐도 낭비가 아니다. 나머지 10건은 M1 뒤에 C~F 가
  바뀔 때 함께 본다.

## 6. 전제 변경 — agrodss 는 몰 중심, DSS 는 납품 농가용 (발행자 2026-09-18)

발행자 결정 셋: ①`d:\agrodss` 별도 신축 ②이식하지 않고 새로 쓴다 — 외부 API 는
**경험**(무엇이 있고 무엇이 없었는지 · 어디서 샜는지)으로만 삼는다 ③**수익은 몰**에서
나오고, DSS 는 그 몰에 납품하는 농가를 위한 것이다. 몰의 대원칙은 **현장 영상이
상세페이지를 대체한다**.

이 전제는 위 §1~§5 를 무효로 만들지 않는다. 트리의 자기 한정 원칙은 그대로다.
바뀌는 것은 **연결의 방향과 무게**다.

### 6-1. 고아가 뿌리가 된다

| 초판 판정 | 재판정 |
|---|---|
| G "사진 → 몰 콘텐츠" 는 트리 밖 참조(§3-3) | **몰이 중심**이다. G 관찰의 대원천이 영상이 되고, 그 영상은 몰이 요구한다 — 농가가 기록할 **상업적 이유**가 생긴다 |
| L 첫해 문제: 기록 부담만 지고 이탈 | **부분 해소** — 첫해 값은 DSS 가 아니라 몰(판로)이 준다. "기록 부담이 순증 아님"의 근거가 인증 장부(조건부)에서 **상세페이지 영상(전 농가)**으로 바뀐다. 더 강한 근거다 |
| J 결과 기록이 빠지기 쉬움 | 몰이 수량·품질·반품을 **자동으로** 닫는다 — 단 아래 6-3 경계 안에서만 |
| M1 첫 농가 = 시스템 밖의 유일한 임계 | 임계가 **몰 개설 + 첫 납품 농가**로 바뀐다. 여전히 시스템 밖이지만 조건이 하나 늘었다(입점) |

### 6-2. 영상은 1층 사실이고, 영상에서 읽은 것은 2층 파생이다

트리 F 의 진입 요건(시각·출처·해상도)을 영상은 **문자 그대로** 만족한다 — 촬영 시각 ·
GPS(필지) · 해상도. 그래서 영상은 1층에 그대로 들어간다. 그러나 *"결구가 충실하다"*
같은 판독은 영상에서 **읽어낸 것**이라 2층이고, 읽는 주체가 LLM/비전이면 트리 I "LLM
은 경계 밖" 과 부딪힌다.

```
1층   영상 파일 + 촬영 시각 + 필지 + 해상도            사실 — 그대로 진입
2층   영상 판독값(생육 상태 · 병징 유무)              파생 — 신뢰 등급 "추정"(E 3분류 최하)
심급  농가가 직접 말한 것("꽃이 안 핀다")               F 최종 심급 — 판독값보다 위
```

**규칙 하나가 필요하다**: 영상 판독값은 판단(3층)의 필요 축이 될 수 없고 **확인 요청의
트리거**만 된다("이 영상에서 병징이 보입니다 — 확인해 주세요"). 판단 축이 되는 순간
E "가장 약한 축이 전체 신뢰도를 정한다"에 의해 전체가 추정 등급으로 떨어진다.

### 6-3. H G1 이 방화벽이 된다 — 가장 무거워지는 규칙

초판에서 G1(농가 판매·재고 상태 → 조언 입력 금지)은 출력 규칙 셋 중 하나였다. 몰 중심
구조에서는 **DSS 가 그 농가의 판매·재고를 정확히 안다**. 그래서 G1 은 규칙이 아니라
**두 시스템 사이의 경계**가 된다.

```
몰 → DSS 로 흐르는 것         결과 기록(수확량 · 품질 등급 · 반품 사유)   J 되먹임 — 허용
                              영상(1층 사실)                              G 관찰 — 허용
몰 → DSS 로 흐르면 안 되는 것   재고 · 주문 잔량 · 몰 수요 예측               조언 입력 — 금지
DSS → 몰 로 흐르는 것          판정 + 관측일 + 판정 기준 (G2)               상세페이지 노출 시
```

**왜 무거운가**: DSS 가 몰 수요를 입력으로 받으면 일차 기능(A1 차이 탐지)이 **납품
최적화**로 휜다 — "올해 이 밭은 평년과 다릅니다"가 "지금 수확하면 몰에 팔립니다"가
된다. 트리 K "시스템 발언이 시장 신호가 된다"가 몰에서는 **첫날부터** 참이다.
F "답하지 않음(가격)"도 같은 축이다 — 몰 가격은 예측이 아니라 **계약**이라 답하지
않음이 아니라 *DSS 의 대상이 아님*으로 재분류된다.

**경계는 검사로 고정한다** — 트리 I "래칫은 지금 참인 명제를 고정". *"3층 판단 함수의
입력 스키마에 재고·주문·수요 필드가 없다"* 가 그 명제다. 그리고 반대편도 본다(CLAUDE.md
"막는 것을 검사하면 통과하는 것도 검사한다"): 결과 기록(수확량·품질)은 **흘러야** 한다.

### 6-4. 몰이 트리에 요구하는 신규 항목

| 항목 | 어디에 | 성격 |
|---|---|---|
| 납품 적합 필지 | B0 용도 → B2 | "출하 불가 필지를 사슬에 태움"의 몰 판 — 몰 기준(인증·품질)에 못 미치는 필지 |
| 몰 요구 기준 | 관통 축 인증 | 인증이 법정 인증만이 아니라 **몰 자체 기준**이 된다 — 2단계 시점 결정은 같다 |
| 영상 촬영 시점 | D 격자 칸 | "이 단계에서 이 장면을 찍는다" — 상세페이지 재료이자 관찰 기록. **작업 칸에 촬영이 들어간다** |
| 상세페이지 노출 판정 | H G2 | DSS 판정을 소비자가 보면 관측일·판정 기준이 반드시 붙는다. **노출 여부는 제품 결정** — 안 보이면 G2 는 내부 규칙으로 남는다 |
| 결과 기록 자동화 | J · G | 몰 정산 데이터가 결과 기록이 된다 — 6-3 경계 안의 필드만 |

### 6-5. 순서(M)가 바뀐다

M 은 DSS 만의 순서였다. 몰이 수익원이면 **몰이 먼저 서고 DSS 가 그 위에 선다**.

```
M0   몰 — 상품 · 주문 · 정산 · 영상 상세페이지          (트리 밖 — 별도 트리 필요)
M1   첫 납품 농가                                       (몰 입점이 조건)
M1'  6-3 경계의 입력 스키마 고정                          ← 신규. 몰과 DSS 가 같은 저장소를 쓰기 전에
M2~  기존과 같음
```

M1' 이 M0 뒤 M2 앞에 오는 이유: 두 시스템이 한 DB 를 쓰기 시작하면 경계는 사후에
못 세운다 — 트리 B "인증·기록은 소급 불가"와 같은 형태다.

### 6-6. 즉시 4건에 하나가 는다

|---|---|---|
| 1~4 | §4 그대로(산출 7종 · 양분 축 · 입력 5종 · 축 최소 고정) | 즉시 |
| **15** | **몰↔DSS 입력 경계(6-3)를 스키마로 고정하고 양방향 검사를 짝으로** | 즉시 — M0 와 M2 사이 |

J "불이행 사유"는 납품 실패 사유 필드로 받을 수 있다. 다만 둘 다 6-3 의 *허용* 쪽
